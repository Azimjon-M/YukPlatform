## Product
Aggregate cargo (yuk) posts from large Telegram groups/channels (10k–100k members), parse them with AI into structured loads, dedupe, and send each driver only the loads matching his filters (route, vehicle type, tonnage) as a personal message with one-tap call. Later: Mini App, web, Android/iOS, and pochta / passenger taxi between cities.

## Layout
- `apps/api` — **control centre server** (Express 5, built 2026-11-05): `npm start` builds `apps/admin`, serves http://localhost:3000/admin on 127.0.0.1 only, and forks the bot and collector as child processes (`src/processes.js`: IPC `"stop"` → graceful, kill after 8 s; crash → restart in 10 s, max 5 per 10 min; 1000-line log ring per process, also echoed as `[bot] …`). The bot process still does dedupe, matching and dispatch itself; the API only reads/edits the same SQLite DB. Contract in `apps/api/README.md`. Security: Host must be localhost, non-GET needs header `x-yuk-admin: 1` (blocks CSRF from other sites); responses carry only booleans for secrets (`configInfo`).
- `apps/admin` — React 19 + Vite control-centre UI (base `/admin/`, dev port 5174 with `/api` proxy): overview tiles + hourly inflow vs processed chart, loads with filters, queue (retry failed), drivers (active toggle), sources (add/enable/remove — collector re-reads the `sources` table every round; seeded once from `TG_SOURCES`), process logs, AI page (placeholder). Never deployed publicly.
- Single instance: bot and collector write `data/run/<name>.json` (PID) via `acquireRunLock` (`@yuk/store`); a second copy exits with an Uzbek message, and the control centre shows a terminal-started one as `external` and refuses to start another.
- `apps/bot` — grammY bot @Yuk_Ekspert_agent: onboarding wizard, settings, worker (queue → parser → dedupe → channel + DMs); also queues posts from groups where it is admin
- `apps/collector` — GramJS userbot reading public groups (`tg:live` polls into the queue); separate process so a ban/crash doesn't take the bot down
- `packages/store` — SQLite via built-in `node:sqlite` (`data/yuk.db`, gitignored): posts queue, loads, drivers, collector cursors. Shared by collector and bot (WAL mode, two processes)
- `apps/web` — React 19 + Vite Telegram Mini App (no Tailwind yet). Now: the driver settings form only (static site, no backend); later the website and a loads feed via `apps/api`
- `apps/mobile` — Expo (phase 4)
- `packages/parser` — post text → JSON (phase 0, current)
- `packages/shared` — domain data and rules used by every app: `regions.js` (14 regions + xorij, cities with all spellings, Tashkent districts, countries, `sameArea`), `vehicles.js` (truck class, body type, loading sides, pallet), `categories.js`, `places.js` (`lookupCity`/`normalizePlaces`), `match.js` (load ↔ driver), `dedupe.js` (load key, deduper)
- `docs/haydovchi-suhbati.md` — **source of domain facts**: answers from Azimjon's truck-driver friend (2026-11-04). Check it before changing vehicle/price/place/matching rules; open questions are listed at its end.
- `data/samples/elonlar.txt` — real posts separated by `---`; contains real phone numbers → gitignored, never publish. Also `gold.jsonl` (hand-checked answers) and `natija-v*.jsonl` (parser runs), all gitignored.

Language: JavaScript (ES modules) by default since he knows JS; revisit TypeScript once `packages/shared` grows. Code comments in Uzbek (he reads them to learn). npm workspaces from the root; `npm test` runs `node --test` per package. Node 24 — `.env` loaded via `node --env-file-if-exists`, no dotenv.

- Gemini: `@google/genai` ^2.32, `models.generateContent` with `config.systemInstruction` + `responseMimeType: "application/json"` + `responseJsonSchema: POST_SCHEMA`; SDK retryOptions (4 attempts, 3→30 s) for 429/5xx; default model alias `gemini-flash-lite-latest` (→ gemini-3.5-flash-lite in 2026-11, ~1.5 s/post, schema followed). Tested 2026-11-04 with his key: `gemini-flash-latest` returned 503 "high demand", `gemini-2.5-flash` 404 "no longer available to new users". Model IDs drift — `npm run parse -- --models` lists what his key sees. Concurrency 2. Free tier hit a **per-minute** 429 after ~16 requests (2026-11-04) and recovered within a minute: `gemini.retryAfterMs` reads `quotaId`/`retryDelay` from the 429 body, and the CLI pauses all workers and retries the same post (max 5 waits). Per-day 429 or 503 → stop, save partial results, print `--skip N`. **Daily free limit = 500 requests per model** (429 body 2026-11-05: `GenerateRequestsPerDayPerProjectPerModel-FreeTier`, quotaValue 500, gemini-3.5-flash-lite); it resets at midnight Pacific = 13:00 Tashkent. The one-request-per-post bot used it up by ~10:05 on 2026-11-05. Each model has its own bucket (his key also sees gemini-3.1-flash-lite, 2.5-flash-lite, 3.5/3.6/3.7/3.8-flash, gemma-4).
- **Batch (2026-11-05):** `parseBatch(texts)` sends N posts in one request (`PARSER_BATCH`, default 10; CLI `--batch N`, `--batch 1` = old mode). `src/batch.js` joins masked posts with `=== POST n ===` headers; `BATCH_SYSTEM_PROMPT` = `SYSTEM_PROMPT` + batch rules (same prefix → implicit cache); `BATCH_SCHEMA` = `{posts: [{id, postType, loads}]}`. `readBatchAnswer` maps by id and is strict: bad JSON, missing/duplicate/unknown id, MAX_TOKENS or block → the whole answer is discarded (a shifted id would glue one post's route to another post's phone) and the group is split in halves and retried down to single posts (fewer requests than one-by-one). 429/503/key errors are thrown to the caller. Results carry `batch: N` or `fallback: reason`; usage only on the first item of a batch. Gold on gemini-3.1-flash-lite (production model's quota was gone): single 418/424, batch 10 → 415/415, 16 → 413/417, 32 → 408/414 (one run missed the ×1000 price rule on a 5-load post); production model, one 10-post batch: 178/180 vs v5 180/180. Batch errors repeat: "tent kerak" → fura, country-only → capital ("Berlin"), "Ref Tent" → tent. Input tokens per post ~5 600 → ~800.
- Claude: `@anthropic-ai/sdk` ^1.4, `client.beta.messages.create` with `output_config.format` (json_schema) + `output_config.effort` (default `low`), cached system prompt, `fallbacks: "default"` + beta `server-side-fallback-2026-07-01` only for opus-5*/fable-5*/sonnet-5-5. Default model `claude-opus-5-5`.
- Phones are NOT asked from the model: regex in `src/phones.js` (right-anchored group matching, rejects prices/cards/dates) and attached to every load of the post. **`maskPhones` replaces them with `[telefon]` before the text goes to the AI** (free Gemini may use inputs; third-party numbers stay local). UZ codes include 87 and 70 (seen as `+998 87…`/`+998 70…` in real posts); +992…+996 neighbours accepted.
- First real run (2026-11-04, 50 posts from public groups, gemini-3.5-flash-lite): 50/50 valid JSON, 100 loads, region-level routes ~all right. Error patterns (all fixed by schema v2 + prompt, see below): vehicle invented as `tent` when the post only says "fura kerak" (67/100 loads are tent); per-kg prices ("kilosiga 200 so'm", "180 kg so'mdan") read as total price or as weight → needs a price unit; city invented from a region ("Surxondaryo" → Termiz); weight ranges averaged ("20 22 ton" → 21); toponyms missed (Baxmal → "Baxt", lowercase "yangi yer" ≠ Yangiyer). Multi-load posts with several phones get all phones on every load.
- Output: `{postType: yuk_bor|mashina_bor|boshqa, loads: [...]}`; `mashina_bor` posts reuse the load fields for the truck's route/capacity.
- **Schema v2** (after the driver interview; `LOAD_PROPERTIES` in `src/schema.js`, enums built from `@yuk/shared`): the old single `vehicle` field is split into `truckClass` (fura / mini_fura / isuzu / kichik / labo — size) and `bodyType` (tent / ref / ploshatka / bort / tral / samosval / sementavoz / sisterna / manipulyator / tyagach / boshqa); plus `fromPlace`/`toPlace` (district, market), `fromCountry`/`toCountry`, `volumeM3`, `pallets`, `loadingSides[]`, `partial` (dogruz / пол груз), `priceUnit` (reys/tonna/kg/kub), `payment` (naqd/karta/otkazma), `negotiable`. Prompt rules that matter (each fixed a real error): weight range → the LARGER number; never default bodyType to tent; a body type alone ("tent kerak") names no truck size; region-only post → city null, never the region capital; so'm trip prices below 100000 are thousands (×1000), per-kg prices are not multiplied; "+300 gpis" is not added to the price (goes to note — meaning still unknown); neighbouring-language words (fiyat, araç, lazim).
- After the AI answers, code rules override it where a rule is more reliable than the model (`src/parse.js`):
  - `normalizePlaces` (shared) overwrites region/country from our city list when the city is unambiguous — the model sometimes puts the right city in the wrong region (Koson → buxoro). Ambiguous names (Yangibozor in 3 regions, Qorako'l) are left as the model wrote them.
  - It also promotes the place to the city when the "city" is really a region name ("Тошкент Назарбекдан" → model: Toshkent + place Nazarbek → city Nazarbek, region toshkent; "Namangan (pop)" → Pop). Not for real cities ("Qo'qon (Uchko'prik)" stays Qo'qon), Tashkent districts, or same-name towns in another region.
  - `cargoCategory` (shared) computes fura/yengil from truckClass, else weight ≥ 10 t; the model said "fura" for a 9 t load. pochta/yo'lovchi untouched.
- **Accuracy check:** `data/samples/gold.jsonl` = 32 hand-checked posts / 52 loads (generated by a scratch script, only trustworthy fields are labelled). `npm run parse -- --only gold --out data/samples/natija-vN.jsonl` re-parses just those posts (`--only 3,27,38` also works); `npm run parse:eval -- --results <a> --results <b> [--details]` prints per-field accuracy side by side and the mismatches. Results 2026-11-04 (gemini-3.5-flash-lite, eval scores v1 against the corrected gold): v1 old schema 85% (362/424) → v3 98% (417) → v4 + code rules 99.3% (421) → v5 99.3% (421). **Run-to-run noise is ±1–2 fields** (the same prompt flips #41 truckClass between runs), so judge a prompt change by the per-field table, not one total. Still unstable: the model sometimes calls a bare "tent kerak" / 12 t load a fura despite the rule (truckClass 86–95%). v5 invented "Berlin" for country-only "Германия" → country rule added after v5, not yet measured. A gold run is 32 requests (~7 min with the per-minute waits).

## Key facts / decisions
- Telegram inline URL buttons accept only `http(s)://` and `tg://` — **no `tel:`**. One-tap call inside Telegram = phone in text as `+998XXXXXXXXX` (auto-linked), or an https redirect page → `tel:` (also gives call analytics). Web/mobile use `tel:` directly.
- Bot vs userbot are both real-time; difference is permission and ban risk, not speed. Bot must be admin to read channels; in groups it needs admin or privacy mode off. Userbot: separate phone number, read-only, don't join many groups at once; session string is a secret.
- Same load is reposted in many groups → each load is sent **once** (driver: "we don't know if it's closed"). `shared/dedupe.js`: key = phones + from + to + bodyType + weight (price/cargo/date left out — reposts change them); identical loads inside one post get `#2`; in-memory `createDeduper` forgets keys after 3 days (window is a guess — move keys to Postgres in `api`).
- Matching (`shared/match.js`, `matchLoad(load, driver)` → `{ok, reasons}`): a field the post doesn't state is no restriction. Weight vs `capacityKg` (or class max), volume vs body L×W×H, pallets vs euro pallets that fit (fura 33); truckClass and bodyType exact when the post names them (Isuzu drivers want only their own loads); loadingSides — any listed side the truck has ("yon" = left or right; left/right seen from BEHIND). Driver `mode: "all"` skips the vehicle check, route is always checked. International loads only with `international: true` (separate mode); `fromAreas`/`toAreas` take region ids, "xorij" or a country name; Toshkent city = region; region-only loads go to drivers of that region; `toAreas` = home region for return loads (obratka — very important to drivers).
- Model category generic from day one (fura / yengil / pochta / yo'lovchi) but launch with fura only.
- Phase 0 first: parser is the biggest technical risk. Phones via regex, the rest via the AI provider (Gemini by default); one post may hold several loads → output an array. Measure accuracy on 30–50 hand-checked posts.

- Business (from the driver): runs 24/7; no live location; employer role later (connect drivers to employers directly); income = subscription + ads; show when the load was posted; no price filter yet (sorting later); posts without a price are still sent.
