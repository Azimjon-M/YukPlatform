## Product
Aggregate cargo (yuk) posts from large Telegram groups/channels (10k–100k members), parse them with AI into structured loads, dedupe, and send each driver only the loads matching his filters (route, vehicle type, tonnage) as a personal message with one-tap call. Later: Mini App, web, Android/iOS, and pochta / passenger taxi between cities.

## Key facts / decisions
- Telegram inline URL buttons accept only `http(s)://` and `tg://` — **no `tel:`**. One-tap call inside Telegram = phone in text as `+998XXXXXXXXX` (auto-linked), or an https redirect page → `tel:` (also gives call analytics). Web/mobile use `tel:` directly.
- Bot vs userbot are both real-time; difference is permission and ban risk, not speed. Bot must be admin to read channels; in groups it needs admin or privacy mode off. Userbot: separate phone number, read-only, don't join many groups at once; session string is a secret.
- Same load is reposted in many groups → each load is sent **once** (driver: "we don't know if it's closed"). `shared/dedupe.js`: key = phones + from + to + bodyType + weight (price/cargo/date left out — reposts change them); identical loads inside one post get `#2`; in-memory `createDeduper` forgets keys after 3 days (window is a guess — move keys to Postgres in `api`).
- Matching (`shared/match.js`, `matchLoad(load, driver)` → `{ok, reasons}`): a field the post doesn't state is no restriction. Weight vs `capacityKg` (or class max), volume vs body L×W×H, pallets vs euro pallets that fit (fura 33); truckClass and bodyType exact when the post names them (Isuzu drivers want only their own loads); loadingSides — any listed side the truck has ("yon" = left or right; left/right seen from BEHIND). Truck class compared by family (katta_fura ⊂ fura, katta_isuzu ⊂ isuzu); body exact except `BODY_ACCEPTS` (ref takes izoterm, ploshatka takes konteyner) and old ids via `bodyId`. The old driver `mode: "all"` is ignored since 2026-11-07 — the vehicle is always checked; the route comes from «📋 Mos yuklar» and no DM goes out before one is chosen. International loads only with `international: true` (separate mode); `fromAreas`/`toAreas` take region ids, "xorij" or a country name; Toshkent city = region; region-only loads go to drivers of that region; `toAreas` = home region for return loads (obratka — very important to drivers).
- Model category generic from day one (fura / yengil / pochta / yo'lovchi) but launch with fura only.
- Phase 0 first: parser is the biggest technical risk. Phones via regex, the rest via the AI provider (Gemini by default); one post may hold several loads → output an array. Measure accuracy on 30–50 hand-checked posts.

- Business (from the driver): runs 24/7; no live location; employer role later (connect drivers to employers directly); income = subscription + ads; show when the load was posted; no price filter yet (sorting later); posts without a price are still sent.
